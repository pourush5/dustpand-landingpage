Engineering Philosophy

Built Upon Conservative Principles

Most "cleaners" act like bulldozers—blindly deleting temp files and registry keys. DustPan acts like an intelligent forensic assistant that helps you decide, stage, and preserve.

Zero Surprise Deletions

DustPan never executes unprompted permanent removals. Instead of shredding files into the void, it moves candidate items to an isolated staging folder with an atomic JSON reversal manifest. Change your mind? Restore all files instantly with a single click.

manifest.json Atomic Rollback DustPan_Review/

Win32 Cloud Hydration Guard

Blind scanners touch every file, triggering massive unwanted downloads from OneDrive or iCloud. DustPan inspects Windows kernel attributes (FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS) to identify dehydrated offline files and skip them safely.

kernel32.dll Reparse Points OneDrive Safe

Cryptographic Header-Hasher

Find true byte-level duplicate files regardless of their names. DustPan uses a 3-stage pipeline: exact byte size grouping, 64 KB header SHA-256 hash checks, and full payload verification. Lightning fast on multi-gigabyte files without wasting I/O.

64KB Fast-Head SHA-256 Checksum Zero False Positives

Inspectable Robocopy Scripts

Don't want to delete large files, but need to offload them to an external SSD or pendrive? DustPan exports standalone Windows batch scripts utilizing native robocopy.exe /Z with restartable transfer resilience. Inspect the script in Notepad before you run it.

robocopy /Z Human Inspectable External USB Ready

100% Local & Zero Telemetry

The application operates as a self-contained local Go HTTP daemon strictly bound to 127.0.0.1:8484. Your file paths, names, directories, and disk hierarchy never leave your PC. Absolutely zero tracking, analytics, or surveillance.

127.0.0.1 Only No Network Snooping Air-Gapped Friendly

Ever had a disk scanner freeze while traversing 200,000 tiny files inside a JavaScript dependency tree? DustPan automatically ignores heavy dev noise such as node_modules, .venv, .git, and build caches, focusing purely on real storage hogs.

// Win32 Cloud-Hydration Detection
package scanner

import (
    "golang.org/x/sys/windows"
    "syscall"
)

// Query kernel32.dll for dehydrated cloud reparse attributes
const (
    FILE_ATTRIBUTE_OFFLINE               = 0x00001000
    FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS = 0x00400000
)

func IsCloudOnlyFile(path string) bool {
    ptr, err := syscall.UTF16PtrFromString(path)
    if err != nil { return false }

    attrs, err := windows.GetFileAttributes(ptr)
    if err != nil { return false }

    // Skip if file is online-only (prevents multi-GB downloads)
    return (attrs&FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS) != 0 ||
           (attrs&FILE_ATTRIBUTE_OFFLINE) != 0
}
